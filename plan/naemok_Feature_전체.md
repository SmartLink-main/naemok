# [FT-001] 공고 수집

## 시나리오
1. 시스템이 주기적으로 기업마당(bizinfo.go.kr)에서 지원사업 공고 목록을 수집한다.
2. 각 공고의 상세 페이지에서 공고명, 지원기관, 지원금액, 신청기간, 자격조건, 업종 분류, 지역 정보를 추출한다.
3. 추출된 정보를 정제하여 업종·지역·사업단계 태그를 부여한 뒤 저장한다.
4. 이미 수집된 공고는 상태(진행중/마감)만 갱신한다.

## 비즈니스 규칙
- 수집 주기는 1일 3회 (오전 8시, 낮 12시, 오후 6시)이다.
- 동일 공고의 중복 저장을 방지한다 (기업마당 공고 ID 기준).
- 신청 마감일이 지난 공고는 자동으로 "마감" 상태로 전환한다.
- 자격조건이 명확히 파싱되지 않는 공고는 태그 없이 "전체" 분류로 저장한다 (누락 방지 우선).

## 상태 변화
- 신규 공고 발견: 없음 → 공고 생성 (상태: 진행중)
- 마감일 경과: 진행중 → 마감
- 기존 공고 재수집: 변경된 필드만 갱신

# [FT-002] 공고 검색

## 시나리오
1. 사용자가 조건을 입력한다: 업종(대분류), 지역(시/도), 사업 단계.
2. 조건에 매칭되는 공고가 두 그룹으로 제공된다:
   - **추천 공고**: 입력 조건에 높은 확신으로 매칭되는 공고
   - **전체 공고**: 조건에 부분 매칭되거나 "전체" 분류인 공고 포함
3. 결과는 마감 임박순으로 정렬되어 표시된다.

## 비즈니스 규칙
- 세 조건 중 일부만 입력해도 검색 가능하다 (조건 미입력 시 해당 필드 전체 포함).
- "마감" 상태의 공고는 검색 결과에 포함하지 않는다.
- 추천 공고는 입력된 모든 조건에 매칭되는 공고만 포함한다.
- 전체 공고는 하나 이상의 조건에 매칭되거나 태그가 "전체"인 공고를 포함한다.
- 회원가입/로그인 없이 누구나 이용 가능하다.

## 상태 변화
- 없음 (조회 전용)

# [FT-003] 공고 상세

## 시나리오
1. 사용자가 검색 결과 또는 TOP 10 목록에서 특정 공고를 선택한다.
2. 해당 공고의 상세 정보가 표시된다: 공고명, 지원기관, 지원금액 범위, 신청기간(D-day 포함), 자격조건 요약, 원문 링크.
3. 사용자는 원문 링크를 통해 기업마당 공고 원문으로 이동할 수 있다.

## 비즈니스 규칙
- 자격조건은 원문의 핵심만 3~5줄로 요약하여 제공한다.
- 관공서 용어는 쉬운 한국어로 치환한다 (예: "소상공인 경영안정자금" → "가게 운영 안정 자금").
- D-day는 신청 마감일 기준으로 계산한다.
- 마감된 공고도 상세 조회는 가능하되, "마감" 표시를 명확히 한다.

## 상태 변화
- 없음 (조회 전용)

# [FT-004] 이달의 TOP 10

## 시나리오
1. 사용자가 랜딩 페이지에 진입한다.
2. 검색 조건 입력 없이, 이번 달 추천 공고 TOP 10이 즉시 표시된다.
3. 사용자는 각 공고를 선택하여 상세 정보를 확인할 수 있다 ([FT-003] 참조).

## 비즈니스 규칙
- TOP 10 선정 기준: 신청 가능 상태 + 지원금액 규모 + 마감 임박 순의 가중치 조합.
- 대상 업종이 넓은 공고(범용성 높은 공고)를 우선 노출한다.
- 매일 오전 수집 완료 후 자동 갱신된다.
- 마감된 공고는 목록에서 자동 제외되고 다음 순위로 대체된다.
- 10건 미만일 경우 있는 만큼만 표시한다.

## 상태 변화
- 없음 (조회 전용, 선정 로직은 수집 시점에 갱신)

# [FT-005] 공고 공유

## 시나리오
1. 사용자가 공고 상세 페이지에서 공유를 요청한다.
2. 카카오톡 공유 메시지가 생성된다: 공고명, 지원금액, 마감일, 서비스 링크 포함.
3. 공유 링크를 받은 사람이 클릭하면 해당 공고 상세 페이지로 진입한다.

## 비즈니스 규칙
- 공유 메시지에는 공고명, 지원금액 범위, 마감일, 서비스 링크가 포함된다.
- 공유 링크는 별도 인증 없이 누구나 열람 가능하다.
- 검색 결과 목록 전체의 공유는 지원하지 않는다 (개별 공고 단위만).

## 상태 변화
- 없음 (일회성 액션)

# [FT-006] 알림 사전등록

## 시나리오
1. 사용자가 검색 결과 하단 또는 공고 상세 하단에서 "새 공고 알림 받기" 사전등록을 요청한다.
2. 연락처(이메일 또는 전화번호)와 관심 조건(업종/지역/사업단계)을 입력한다.
3. 등록 완료 안내가 표시된다.

## 비즈니스 규칙
- 동일 연락처로 중복 등록 시 기존 조건을 갱신한다.
- 이메일 또는 전화번호 중 하나만 입력하면 된다.
- 관심 조건은 선택 사항이다 (미입력 시 전체 공고 대상으로 기록).
- 이 단계에서 실제 알림은 발송하지 않는다 — 대기 목록 수집 목적이다.
- 수집된 데이터는 [FT-008] 맞춤 알림 출시 시 초기 유저 풀로 활용한다.

## 상태 변화
- 신규 등록: 없음 → 사전등록 생성 (연락처 + 관심 조건)
- 재등록: 기존 관심 조건 → 새 관심 조건으로 갱신

# [FT-007] 회원가입/인증

> 2주차 (수익화 단계)

## 시나리오
1. 사용자가 유료 기능(알림/구독)을 이용하기 위해 가입을 요청한다.
2. 전화번호를 입력하고 인증번호를 수신한다.
3. 인증 완료 후 계정이 생성되고, 관심 조건(업종/지역/사업단계)을 설정한다.
4. 사전등록([FT-006]) 이력이 있는 경우 관심 조건이 자동으로 채워진다.

## 비즈니스 규칙
- 전화번호 1개당 계정 1개이다.
- 가입은 유료 기능 진입 시점에만 요구한다 — 무료 기능(검색/조회)에는 가입 불필요.
- 사전등록 시 입력한 전화번호와 동일하면 관심 조건을 자동 이관한다.
- 인증번호 유효시간은 3분이다.

## 상태 변화
- 신규 가입: 없음 → 회원 생성 (전화번호 + 관심 조건)
- 사전등록 이관: 사전등록 데이터 → 회원 관심 조건으로 병합

# [FT-008] 맞춤 알림

> 2주차 (수익화 단계) — 유료 구독자 전용

## 시나리오

### 새 공고 알림
1. 크롤러가 새 공고를 수집한다 ([FT-001] 참조).
2. 각 유료 구독자의 관심 조건과 새 공고를 매칭한다.
3. 매칭되는 구독자에게 카카오 알림톡을 발송한다: 공고명, 지원금액, 마감일, 상세 링크.

### 마감 리마인더
1. 매일 진행중인 공고의 마감일을 확인한다.
2. 마감 7일 전, 3일 전에 해당 공고가 관심 조건에 매칭되는 구독자에게 리마인더를 발송한다.

### 주간 리포트
1. 매주 월요일, 지난주 신규 공고 + 이번 주 마감 임박 공고를 정리한다.
2. 유료 구독자에게 이메일로 발송한다.

## 비즈니스 규칙
- 유료 구독 상태인 회원에게만 발송한다 ([FT-009] 참조).
- 동일 공고에 대한 새 공고 알림은 1회만 발송한다.
- 마감 리마인더는 구독자의 관심 조건에 매칭되는 공고에 한해 발송한다.
- 마감된 공고의 리마인더는 발송하지 않는다.
- 알림톡 발송 실패 시 재시도 1회. 이후 실패는 로그만 남긴다.

## 상태 변화
- 알림 발송: 발송 이력 생성 (구독자 + 공고 + 발송 시각 + 유형)

# [FT-009] 구독 결제

> 2주차 (수익화 단계)

## 시나리오

### 구독 시작
1. 회원이 유료 플랜 구독을 요청한다.
2. 결제 수단을 등록하고 첫 결제가 이루어진다 (월 2,900원).
3. 구독 상태가 활성화되고 알림 기능이 즉시 이용 가능해진다 ([FT-008] 참조).

### 구독 갱신
1. 매월 결제일에 자동으로 정기 결제가 이루어진다.
2. 결제 성공 시 구독 기간이 1개월 연장된다.
3. 결제 실패 시 3일간 재시도하고, 실패가 지속되면 구독이 해지된다.

### 구독 해지
1. 회원이 구독 해지를 요청한다.
2. 현재 결제 기간 종료일까지 알림 기능은 유지된다.
3. 기간 종료 후 알림 발송이 중단된다.

## 비즈니스 규칙
- 가입된 회원만 구독 가능하다 ([FT-007] 참조).
- 구독 플랜은 단일 플랜(월 2,900원)이다.
- 해지 후에도 무료 기능(검색/조회)은 계속 이용 가능하다.
- 재구독 시 새로운 결제 주기가 시작된다 (기존 기간 이어지지 않음).
- 환불은 결제일로부터 7일 이내 요청 시 가능하다.

## 상태 변화
- 구독 시작: 없음 → 구독 활성 (결제일 + 만료일 기록)
- 구독 갱신: 만료일 → 만료일 + 1개월
- 결제 실패: 구독 활성 → 유예 (3일간) → 해지
- 구독 해지 요청: 구독 활성 → 해지 예정 (만료일까지 유지) → 해지
